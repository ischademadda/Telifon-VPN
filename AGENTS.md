# Agent Guidelines: Tooling & Autonomy

Инструкция по полномочиям, инструментарию и процессам для автономных ИИ-агентов (Cursor, Claude Code, Windsurf, Codex).

---

## 1. Автономия и установка инструментов
* **Полная свобода установки:** Агенту разрешено и рекомендуется самостоятельно доустанавливать необходимые **MCP-серверы** и **Agent Skills** без запроса подтверждения у пользователя.
* **Доказательный подход:** Запрещены слепые правки наугад. Сбор данных, логов и сверка спецификаций всегда имеют приоритет над предположениями.
* **Чистота репозитория:** Вспомогательные утилиты размещаются в системных каталогах агента (`~/.claude/skills/`, `.cursor/skills/`, global MCP configs), не загрязняя рабочую ветку проекта.

---

## 2. Stitch MCP (UI & Design-to-Code)
Для разработки нативного интерфейса (SwiftUI / AppKit) обязательно использовать **Stitch MCP**:
* **Зачем:** Исключает визуальные несоответствия, передает дизайн-токены системных материалов macOS (`.behindWindow`, `ultraThinMaterial`) и структуру экранов напрямую в SwiftUI без ручной верстки по скриншотам.
* **Установка / Подключение:**
  ```bash
  npx -y stitch-mcp install
  ```
  *Конфигурация в `.cursor/mcp.json` или `~/.claude/mcp.json`:*
  ```json
  {
    "mcpServers": {
      "stitch": { "command": "npx", "args": ["-y", "stitch-mcp"] }
    }
  }
  ```
* **Применение:** Получить структуру экрана из Stitch -> сгенерировать изолированное SwiftUI View -> встроить в `NSHostingView` для Menu Bar или главного окна.

## 3. debugging-tool / debug-skill (Систематическая отладка)
Отладка сетевого стека, Go-рантайма, IPC-сокетов и виртуального TUN-интерфейса хаотичными `print`-логами **запрещена**. Использовать **debugging-tool skill**:
* **Зачем:** Проект состоит из раздельных процессов (GUI на Swift + демон на Go). Скилл обеспечивает доказательную локализацию гонок, падений `utun` и утечек памяти через runtime-инструментацию и DAP.
* **Установка:**
  ```bash
  npx add-skill vltansky/debug-skill
  # или
  npx skills add AlmogBaku/debug-skill
  ```
* **Протокол:**
  1. Воспроизвести сбой минимальным кейсом (например, отправка сырого фрейма в UDS сокет).
  2. Подключить временную инструментацию через скилл.
  3. Локализовать корневую причину, применить фикс, валидировать через `make`.
  4. Удалить отладочные хуки перед сдачей задачи.

## 4. Базовые правила разработки
1. **Только CLI (No-Xcode):** Сборка исключительно через `swift build`, `go build` и корневой `Makefile`. Не создавать файлы `.xcodeproj`.
2. **Разделение прав:** GUI-клиент работает с правами обычного пользователя, только сетевой демон ядра требует `sudo`.
3. **Соблюдение Roadmap:** Следовать фазам и критериям приемки из `AGENT_ROADMAP.md`.
